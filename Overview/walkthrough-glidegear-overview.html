04 Core Business Flows

Order flow (CreateOrder)

1. Frontend POST /api/orders { shippingAddress, paymentSummary } 2. Controller reads basketId from Cookie 3. Load Basket (Include Items → Product) 4. For each Item: - Check sufficient stock? If not → 400 "Some items out of stock" - Create OrderItem (price snapshot) - Deduct Product.QuantityInStock 5. Calculate Subtotal + DeliveryFee 6. Write Order + OrderItems (same transaction) 7. Return 201 Created + OrderDto

Payment success callback

1. Stripe POST /api/payments/webhook 2. ConstructStripeEvent validates signature 3. Check intent.Status == "succeeded" 4. Find Order by PaymentIntentId 5. Verify order.GetTotal() == intent.Amount (anti-tampering) - Match → OrderStatus = PaymentReceived - Mismatch → OrderStatus = PaymentMismatch 6. Delete Basket (prevent duplicate payment) 7. Return 200 OK

Payment failure callback

1. intent.Status != "succeeded" 2. Find Order by PaymentIntentId 3. For each OrderItem: - product.QuantityInStock += item.Quantity (rollback inventory) 4. OrderStatus = PaymentFailed 5. Return 200 OK

06 Database Core Relationships

User (1) ──(1:1)── Address User (1) ──(1:N)── Basket (via Identity) Basket (1) ──(1:N)── BasketItem BasketItem (N) ──(N:1)── Product Order (1) ──(1:N)── OrderItem OrderItem (N) ──(N:1)── ProductItemOrdered (snapshot, not FK)
💡 OrderItem.ItemOrdered is a snapshot, does not reference Product foreign key. Price, name, and image URL are fixed at order time.

07 Key Design Decisions

Decision PointChoiceReasonTrade-off
Shopping cart persistence Cookie + DB Works for unauthenticated users, persists after login Cookie 30-day expiry, weaker security than Token
Order price storage Snapshot (OrderItem.Price) Historical orders immune to product price changes Slightly more storage for Price field
Inventory deduction timing At order placement (not payment) Prevents overselling, locks inventory Inventory held until payment; rollback on failure
Payment failure handling Webhook auto-rollback Automated, no manual intervention needed Relies on Stripe callback delivery; network issues need retry
Database choice PostgreSQL Reliable, well-supported, good performance Migration from SQL Server requires schema changes
